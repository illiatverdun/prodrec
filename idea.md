# prodrec — ідея проєкту

## Одним реченням

Трекер робочих днів для фрілансерів і контракторів, який показує **чистий
прибуток** — після податків, комісій і конвертації валют.

## Проблема

Фрілансер бачить суму в контракті («€400/день»), але не бачить, що залишиться
на руках. Між ставкою та реальними грошима стоять:

- податок — свій відсоток у кожній країні та в кожного ФОПа;
- комісія платформи, банку або посередника;
- курс валют — контракт в одній валюті, витрати в іншій;
- кілька проєктів одночасно з різними ставками.

Наприкінці кожного місяця треба порахувати дні по кожному клієнту, помножити
на ставку, відняти податок і комісію, зрозуміти реальну суму — і виставити
інвойс.

Зараз це роблять у Google Calendar + Excel: 20–40 хвилин ручної роботи щомісяця,
забуті дні, помилки в формулах, плутанина з валютами.

## Рішення

prodrec замінює календар і табличку одним інструментом.

Календар, у якому фрілансер відмічає робочі дні та обирає проєкт для кожного
дня. Застосунок сам рахує брутто, віднімає податок і комісію та показує
чистий прибуток у потрібній валюті за актуальним курсом.

Без реєстрації, без таймерів, без складних дашбордів. Відкрив — відмітив —
закрив.

## Основний сценарій

1. Створюю проєкти («Клієнт А», «Клієнт Б») — у кожного своя назва й колір.
2. Задаю ставку (€/год) і кількість годин на день для кожного проєкту.
3. У календарі протягую мишкою по днях і призначаю їм проєкт.
4. Задаю відсоток податку та суму комісії для цього місяця.
5. Обираю валюту, в якій хочу бачити результат.
6. Бачу: відпрацьовано днів, брутто, податок, комісія, **чистими на руки**.

Формула:

```
брутто  = дні × години на день × ставка
        − податок (% від брутто)
        − комісія (фіксована сума за місяць)
        = чистий прибуток
```

## Модель обліку

Основна одиниця — **день**. Це відповідає тому, як реально працюють
контрактники: домовляються про ставку за день, а не рахують хвилини.

Технічно денна ставка складається зі ставки за годину × годин на день
(за замовчуванням 8). Це дозволяє описати неповний день, не ламаючи денної
логіки.

Наступний крок — можливість перевизначити години для конкретного дня, якщо
день був неповний або поділений між двома проєктами. Дні залишаються основою,
години — уточнення поверх них.

Повноцінний таймер зі старт/стоп (як Toggl) — **не мета** цього проєкту.

## Для кого

**Основна аудиторія:** фрілансер-одинак на day-rate — розробник, дизайнер,
маркетолог, який працює як B2B (ФОП в Україні, JDG у Польщі, freelance у
Німеччині чи Швейцарії) з 1–3 клієнтами одночасно. Не команда, не студія,
не бухгалтер.

Головний сценарій: раз на тиждень відмітити дні, а в кінці місяця подивитись
підсумок.

**Додаткові сегменти:** digital nomads, part-time консультанти, креативники
(фотографи, відеографи — рахують у «знімальних днях»), репетитори.

## Чому не Toggl / Harvest / FreshBooks

| Вони | prodrec |
| --- | --- |
| Трекають години (start/stop) | Трекає дні (клік або drag) |
| Потрібна реєстрація | Працює одразу |
| $10–25/міс | Безкоштовно |
| Не рахують чистий прибуток | Податок + комісія = net profit |
| Універсальні, для всіх | Зроблений для day-rate контракторів |

Справжній конкурент — не SaaS, а Excel і Google Calendar.
Позиціонування: «викинь свою табличку».

## Що вже працює (v1)

- **Календар на місяць** — призначення проєктів через клік або drag по днях
- **Кілька проєктів** — у кожного своя назва, колір і ставка
- **Податок і комісія** — окремі значення для кожного місяця, з автоматичним
  наслідуванням від попереднього (rolling defaults)
- **Три валюти** — EUR, PLN, UAH з живим курсом (оновлюється, кешується на
  6 годин, є офлайн-фолбек)
- **Приховування вихідних** — окремо для кожного місяця
- **Calendar + List** — два способи переглядати відмічені дні
- **Без реєстрації** — дані зберігаються в браузері (localStorage)

## Найближчий фокус

**Довести дизайн до ладу** — інтерфейс, типографіка, стани елементів,
адаптивність під мобільний. Функціонал уже покриває основний сценарій, тому
пріоритет зараз — якість подачі, а не нові фічі.

Далі — PDF-експорт за paywall, акаунти, перший публічний запуск.

## Бізнес-модель — гіпотеза

Freemium. Нічого з платного ще не збудовано, це напрямок, а не план релізу.

| Free (назавжди) | Pro (~$3/міс) |
| --- | --- |
| Повний трекінг днів | Генерація PDF-інвойсу |
| Податок, комісія, чистий прибуток | Хмарна синхронізація |
| Три валюти з живим курсом | Річний огляд доходів |
| Необмежені проєкти | Кастомні шаблони інвойсів |
| Без реєстрації, дані в браузері | |

## Ідеї на потім

Порядок не визначено, вирішуємо за ситуацією:

- експорт інвойсу для клієнта (PDF або CSV);
- акаунти та синхронізація між пристроями (Supabase), щоб дані не жили лише
  в одному браузері;
- річний огляд і статистика по проєктах;
- Pro-тариф через Stripe;
- години для окремого дня (частковий день, два проєкти в одному дні).

## Технічний контекст

Свідомо простий стек, без складної збірки:

- React 18, підключений напряму (без webpack/vite);
- `timetracker.jsx` — вихідний код, який редагуємо;
- `build.js` — збирає з нього готовий `index.html` (Babel: JSX → JS);
- `index.html` — один самодостатній файл (~190 KB), який і публікується;
- дані — localStorage; курси валют — CDN-API (jsdelivr);
- хостинг — GitHub Pages, оновлюється автоматично після пушу.

Живий сайт: https://illiatverdun.github.io/prodrec/
